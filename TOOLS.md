# Barclay House – free tool stack (installed & tested 3 Nov 2026, box: 8 CPU, 15 GB RAM, **no GPU**)

All free/open-source, no keys or credits. All tests ran on copies in `tests/` – `out/barclay_scene.blend` was never written.

| Tool | Installed | Tested | How to use on this project | Caveats |
|---|---|---|---|---|
| **Blender MCP** camera-match (`camera_match.py`) | y (`/workspace/barclay/camera_match.py`) | y – synthetic round-trip exact (lens 12.00→12.00 mm, 0.000 m, 0 px); CGI `refs/plans_p1_cgi.png` solved: 23.0 mm, cam at 1.72 m eye height, RMS 23.6 px (1.8 % of width) | `blender -b -y tests/scene_copy.blend -P camera_match.py -- --ref refs/<photo> --points tests/cgi_points.json --render tests/match.png --scale 0.5 --hide-near 8 --save tests/matched.blend`. Via MCP: `exec(open('/workspace/barclay/camera_match.py').read(),{'__name__':'camera_match'})` then `match(ref, points)`. Points = ≥5 known corners in hero-local metres + pixel coords. Manual mode: `--fov-h --loc --look`. | Pixel points were read by eye from a 50 px grid → ~20 px error. Solved CGI camera lands inside our viaduct pier set-dressing (pier spacing is NOT_FOUND), so its test render needs `--hide-near`; the hero facade lines up in `tests/match_render_overlay.png`. Use `-y` or the scene renders black/unlit. |
| Render-vs-reference check (`ref_check.py`) | y | y – `tests/match_render_check.png` (ref / render / blend / edge overlay) | `python3 ref_check.py <render.png> <ref.png>` after every model change; read the sheet. | The edge-F1 score is weak (0.51 matched vs 0.50 for an unmatched view); use precision (0.79 vs 0.54) and your eyes, not F1 alone. |
| **teardown** skill (elvarofficial/teardown, MIT) | y – repo `~/apps/addons/teardown` (npm + Playwright Chromium), user skill `/home/box/agent-data/workflows/teardown/SKILL.md` | y – upstream `v8-film` page built and a still captured (SwiftShader software GL); Blender fly-through + `sheet.mjs` beat sheets on the copy scene | `blender -b -y tests/scene_copy.blend -P flythrough.py -- --out tests/fly --res 320x180 --fps 6 --samples 8 --tod golden_hour` → `ffmpeg -framerate 6 -i tests/fly/f_%04d.png -pix_fmt yuv420p tests/fly/fly.mp4` → `node ~/apps/addons/teardown/sheet.mjs --video tests/fly/fly.mp4 --timeline tests/fly/timeline.json --cols 3`. Edit beats in `flythrough.py` SCRIPT; `--keyframe` bakes `Cam_Fly` for final renders. | teardown itself builds three.js machine pages, not Blender scenes; we use its rules (reference first, pure `render(t)`, timeline beats, contact-sheet review) and its `sheet.mjs`. The first sheet caught 2 beats inside the viaduct; fixed in v2 (`tests/fly/fly_sheets/beats-1.png`). Blender 4.2 Cycles (Embree) segfaulted once after 61 frames; rerun resumes (finished frames skipped). ~2 s/frame at 320×180. |
| **BlenderGIS** (domlysz, GPL) | y – `~/.config/blender/4.2/scripts/addons/BlenderGIS` (enabled) | y – EA DTM imported as georeferenced DEM on a copy (`tests/scene_copy_gis.blend`): 819×809 m, 25.7–43.6 m ODN, 33.25 m at hero | Scene georef EPSG:27700, origin 383889.38 E / 397518.84 N (hero centroid, same as `prep.py`). Import `lidar/dtm_georef_bng.tif` (DEM, subdivision **subsurf**). See `tests/gis_test.py`. Lower the DEM by street ODN to match scene z=0. | Original `lidar/*.tif` have no tiepoint/pixel-scale tags → wrong extent; use the rewritten `lidar/dtm_georef_bng.tif` (DSM can be fixed the same way). "mesh" subdivision OOM-killed (10.7 GB) and needed a 1-line patch (int sizes, `georaster_utils.py`); use subsurf. 27700 added to its CRS list per run. No GDAL/pyproj inside Blender (not needed for same-CRS). Its OSM/basemap downloads need internet. |
| **COLMAP** 3.13 (conda-forge, `~/apps/mamba/envs/colmap/bin/colmap`) | y | y – CPU (`--FeatureExtraction.use_gpu 0`, `--FeatureMatching.use_gpu 0`): 50 synthetic fly frames → 43 registered, 1,484 points, 0.51 px reprojection, ~5 s | Run on real site photos/video frames: feature_extractor → sequential/exhaustive_matcher → mapper (see `tests/sfm/`). | apt has no colmap here (apt mirror broken); conda build. Test used our own renders, not real photos: **real splats need site photos/video, which we don't have**. |
| **OpenSplat** 1.2.2 (CPU Gaussian-splat trainer, AGPL) – replaces Nerfstudio | y – built from source `~/apps/OpenSplat/build/opensplat` (CPU libtorch env `~/apps/mamba/envs/splat`) | y – 300 steps on the COLMAP model in 29 s → `tests/sfm/splat_test.ply` | `LD_LIBRARY_PATH=~/apps/mamba/envs/splat/lib ~/apps/OpenSplat/build/opensplat <colmap_dir> -n 7000 -o out.ply` | CPU only: fine for small/low-res sets; a real street scan at 1–2k px will take hours. |
| Nerfstudio / gaussian-splatting (INRIA) | n | n | — | Need an NVIDIA CUDA GPU (splatfacto/gsplat, diff-gaussian-rasterization). Not installable usefully on this box; OpenSplat covers the same step on CPU. |
| **KIRI 3DGS Render** add-on | y – v3.0.0 (last release supporting Blender 4.2; v4.1+ needs 4.3, v5 needs 5.1) as extension `dgs_render_by_kiri_engine` | y – imported a synthetic 3DGS .ply and the OpenSplat `splat_test.ply` (5,936 splats) into the copy scene; EEVEE render of splats works under xvfb software GL (`tests/kiri_splat_eevee.png`) | N panel → 3DGS Render → Import PLY As Splats; or `bpy.ops.sna.import_ply_as_splats_8458e(filepath=...)`. Splats render in **EEVEE** and composite with the Cycles scene. | EEVEE on software GL is slow; older version than current docs. |
| SuperSplat viewer/editor | n (web app) | n | Free in the browser: https://superspl.at/editor – drag a .ply to crop/clean splats before KIRI import. | Needs a browser with WebGL; nothing to install. |
| **TRELLIS** (Microsoft, MIT) | n (source cloned for reference at `~/apps/addons/TRELLIS`) | n | — | README: needs an NVIDIA GPU with ≥16 GB VRAM + CUDA toolkit; no CPU path. Not forced. Free alternative: the public Hugging Face TRELLIS demo in a browser (free tier, queues). |

Side effects to know: Blender 4.2 user prefs (`~/.config/blender/4.2/config/userpref.blend`) were re-saved with BlenderGIS + KIRI enabled; the Blender MCP add-on is still enabled by its own start script. The running MCP Blender session was not touched (it sees the new add-ons after a restart).
